# Changelog

## 2.2.2

Proxmox VE fixes:

- **No more Debian stock kernel on Proxmox nodes.** The CUDA/DKMS step installed `linux-headers-amd64`, which pulls in `linux-image-amd64` (Debian's kernel). On a node with a host DKMS module (NVIDIA) its build failed and left dpkg broken. Proxmox VE now gets `proxmox-default-headers` and `proxmox-headers-$(uname -r)`. Nodes hardened with an earlier 2.2.x can drop the stray kernel with `apt-get purge 'linux-image-*+deb13-amd64' 'linux-headers-*+deb13-*' linux-headers-amd64` (check `apt-get -s` first).
- **Audit rules no longer stop the run on Proxmox VE when other rule files repeat them.** Nodes that carry an earlier CIS script's `/etc/audit/rules.d/50-*.rules` made `augenrules --load` exit 1 with only `Rule exists` errors (every rule was loaded). Those are now a warning; any other auditctl error still fails. Other distributions are unchanged.
- **FIPS provider loads on Proxmox VE nodes with a custom `openssl_conf`.** A node whose `openssl.cnf` named another init section (`openssl_conf = default_conf`) kept that name, so the managed `[openssl_init]` (FIPS + default providers) was never read and validation failed. On Proxmox VE `openssl_conf` now always points at `openssl_init`. Other distributions are unchanged.

- **Root SSH password lockout.** New `PVE_ROOT_PASSWORD_FROM` (CIDRs, default empty): root keeps password login from those networks through a `Match User root Address …` block; everywhere else root stays key-only. The key-only warning no longer looks at `/root/.ssh/authorized_keys`, which on Proxmox links to `/etc/pve/priv/authorized_keys` and always holds the cluster nodes' keys. It now always warns when root is key-only and no password networks are set.
- **faillock no longer locks root on Proxmox VE.** `even_deny_root` and `root_unlock_time` are left out there, because the web UI login (`root@pam`) uses the same PAM stack and anyone on the network could lock root out of both SSH and the web UI. `deny`, `unlock_time` and `fail_interval` still apply to every other user.
- **unattended-upgrades keeps other tools' settings.** `52unattended-upgrades-harden` no longer uses `#clear`, so its `Allowed-Origins`, `Origins-Pattern` and `Package-Blacklist` entries add to existing configuration instead of replacing it. On Proxmox VE, `origin=Proxmox,codename=${distro_codename}` is added to `Origins-Pattern`.
- **No more `-bash: TMOUT: readonly variable` at login (all distributions).** `60-harden.sh` only set TMOUT when it was unset, but never looked at existing TMOUT settings that run after it (a later `/etc/profile.d` file, `/etc/bash.bashrc`, root's dotfiles). Those assignments are now guarded (`[ -n "${TMOUT:-}" ] || …`, backed up first), so they apply only when TMOUT isn't set yet. Other users' dotfiles are reported, not edited.
- **EL8: `/etc/profile` no longer broken (all earlier versions).** EL8 sets umask inside an `if … then umask 002 else umask 022 fi`. The script commented both lines out, leaving empty branches: a syntax error that stopped `/etc/profile`, so no `/etc/profile.d` script (TMOUT, umask) ran at login. Weak umask values are now raised to `027` in place, lines commented out by earlier versions are restored as `umask 027`, and every edit to a shell startup file is checked with `bash -n` before it is installed.
